# migration-log.md — LegacyOrderDesk → OrderDesk.Web

One line per accepted decision or workaround. Later modules append to this file; the console's trace panel is the
live version of it.

## Module 1 · Migration discovery (2026-09-09)

- **Assessment first.** 14 items inventoried and classified (4 direct-port · 5 adapt · 3 redesign · 1 defer · 1 remove) before any namespace was replaced. See `MigrationAssessmentWorkbook.md`.
- **Startup → `Default.json` + `Program.Main`.** `Application.EnableVisualStyles` / `Application.Run` have no equivalent; `Program.Main(NameValueCollection)` runs once per browser session and sets `Application.MainPage`. Kestrel (`Startup.cs`, `app.UseWisej()`) owns the process.
- **Business logic copied verbatim.** `Domain/` (Order, Customer, OrderService, CustomerService, InvoiceDocument, SampleData) has no UI or desktop dependency and moved unchanged. Totals are identical on both sides.
- **Static current user is a defect, not a style issue.** `AppState.CurrentUser` is one slot per server process; a second session overwrites it. Kept in `Legacy/` next to `Application.Session.User` so the leak is reproducible; the typed session context is Module 4's job.
- **Print Invoice → server PDF.** `PrintDocument` targets a printer attached to the server. The shared `InvoiceDocument` lines are written by a dependency-free `InvoicePdfWriter` and shown in a `PdfViewer` (+ Download). No printer, no local path.
- **Export to Excel → bytes + `Application.Download`.** Excel Interop is not supported in a server process and `C:\Orders\out.xlsx` is the user's disk. First slice ships CSV built in memory; Module 6 upgrades to a managed .xlsx writer and a report queue.
- **Attach file deferred to Module 6.** `OpenFileDialog` + `C:\Orders\Attachments` cannot exist on the server; the button logs the boundary instead of faking it. Replacement: `Upload` control + configured storage root.
- **Connection string → `Web.config`.** `App.config` is gone; settings live in the web host's configuration (`<appSettings>`, `<connectionStrings>`), read in Module 2.
- **Window-size restore removed.** The browser window belongs to the user; responsive layout (Module 7) replaces it.
- **Installer / ClickOnce deferred.** The web app is deployed once; checklist in Module 7.
- **Modal dialogs do not block in Wisej.NET.** `ShowDialog(callback)` / `ShowDialogAsync()`; the caller disposes the dialog when it closes (Module 3 rule, already applied to the invoice preview).

## Module 2 · Project conversion and startup (2026-09-10)

- **Path B — branch + clean shell.** Migration branch created; a new Wisej.NET 4 project `OrderDesk.Web` (`Microsoft.NET.Sdk.Web`, `net10.0-windows;net10.0`, `Wisej-4` 4.1.0) sits next to `LegacyOrderDesk` in `OrderDesk.slnx`. Forms are moved *in*; the desktop project is never edited, so it stays the reliable backup and the reference build. See `ShellAnatomy.md`.
- **Startup files accepted as the replacement for `Program.Main`.** `Default.html` (client), `Default.json` (`"startup": "OrderDesk.Program.Main, OrderDesk"`, theme, debug), `Program.cs` (`Main(NameValueCollection)` once per session → `Application.MainPage`), `Startup.cs` (`app.UseWisej()`, file server minus `.json`, Kestrel), `Web.config`. `"mainWindow"` is the documented alternative; the samples keep `"startup"` because it mirrors the lesson.
- **`AddWisej()` does not exist in Wisej-4 4.1.0.** The video's `builder.Services.AddWisej();` line does not compile; `app.UseWisej()` is the only registration. Recorded so nobody chases it.
- **`EnableVisualStyles` / `SetCompatibleTextRenderingDefault` / `[STAThread]` / `Application.Run` deleted with the WinForms `Program.cs`.** They describe one process with one message loop for one user; the theme is `Default.json`'s, Kestrel is the process, sessions are the users. The blocking `LoginForm.ShowDialog()` before `Run` is not ported — sign-in becomes per-session state in Module 4.
- **Namespace swap accepted as mechanical.** `System.Windows.Forms` → `Wisej.Web`, `namespace LegacyOrderDesk` → `namespace OrderDesk`: one search-and-replace over `OrdersForm`, `OrdersForm.Designer`, `EditOrderDialog`, `EditOrderDialog.Designer`. The base class stays `Form` (`FormVsPage.md` — the video's `: Page` is a valid one-line alternative, deferred to the Module 3 navigation decision).
- **Compiler errors categorized before editing.** 39 error lines over four passes (15 → 24 → 10 → 0) in five buckets: namespace/using 2 · control substitution 26 · irrelevant styling 3 · unsupported desktop op 8 · unclear/deferred 0 (silent differences). The count rises after pass 1 because the compiler cannot bind member accesses on unresolved field types. See `CompilerErrorLog.md`.
- **Control substitutions accepted:** `MenuStrip` → `MenuBar` (Dock Top), `ToolStripMenuItem` → `MenuItem`, `DropDownItems`/`Items` → `MenuItems`, `ToolStripItem[]` → `MenuItem[]`, `StatusStrip` → `StatusBar` (Dock Bottom, `ShowPanels`), `ToolStripStatusLabel` → `StatusBarPanel` (Spring), `Form.MainMenuStrip` deleted, `FormBorderStyle.FixedDialog` → `Fixed`. `DataGridView` + columns, `GroupBox`, `Label`, `Button`, `ComboBox`, `TextBox`, `Anchor`, `ClientSize` compiled unchanged.
- **Desktop ops commented, not deleted.** `RegistrySettings.Load/Save`, `InvoicePrinter.Print`, `ExcelExport.ExportOrders`, `SettingsForm`, `OpenFileDialog + C:\Orders\Attachments` stay in `OrdersForm.cs` as the original lines tagged `✕ compiler: <category>` with a one-line stand-in that toasts and raises `BoundaryHit` — the console logs each as `⚠ boundary`. Real replacements: Module 4 (registry, settings, login), Module 6 (print, export, attach).
- **App.config → Web.config, read with `XDocument`.** `ConfigurationManager.ConnectionStrings["OrderDesk"]` looks for `<exe>.config` next to the binary — `Legacy/AppConfig.cs` reproduces it and throws `FileNotFoundException` on the web host. `Configuration/WebConfig.cs` reads `<connectionStrings>/add[@name='OrderDesk']` (and `<appSettings>`) from `Path.Combine(Application.StartupPath, "Web.config")` with `System.Xml.Linq`; no `System.Configuration` reference; passwords masked before anything reaches a banner or a log.
- **`ShowDialog` result — minimal fix now, rule in Module 3.** `if (dialog.ShowDialog(this) == DialogResult.OK)` compiles but the branch never runs (the call returns immediately). Replaced by `dialog.ShowDialog(this, (form, result) => { …; form.Dispose(); })` in the two callers; the `using (var dialog …)` block was dropped because it disposed the dialog while still open. `MessageBox.Show("Saved.")` kept — a notification works as-is; every MessageBox whose return value is read is on the Module 3 list.
- **Non-modal `Form.Show()` disposes on close.** The ported `OrdersForm` floats over the page; the console keeps one instance per session (`BringToFront()` on a second click) and hooks `FormClosed` to clear its reference. Recorded because `ShowDialog` behaves the other way round (caller disposes).
- **Deferred to later modules (open items, 11):** registry settings + `SettingsForm` + `LoginForm` + static `AppState` (Module 4); `ShowDialog`/`using`/MessageBox return values (Module 3); print, Excel export, attach (Module 6); `DataSource = every row` (Module 5).
- **Not copied from LegacyOrderDesk on purpose:** `Program.cs`, `LoginForm` (+ Designer), `SettingsForm` (+ Designer), `Settings/RegistrySettings.cs`, `Reporting/InvoicePrinter.cs`, `Reporting/ExcelExport.cs` — each is either the process model or a desktop boundary; `Legacy/AppState.cs` and `Legacy/AppConfig.cs` are copied only to show the failure live.
